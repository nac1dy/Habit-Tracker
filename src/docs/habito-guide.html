01 · Architektur

Das große Bild

Habito besteht aus 4 Screens, geteilten Komponenten, einer Datenschicht und einem API-Layer. Alles hängt zusammen — aber jedes Teil ist isoliert austauschbar.

Warum so aufgeteilt?
Jeder Coder arbeitet in einer Datei / einem Ordner ohne die Arbeit anderer zu berühren. Die geteilten Komponenten (BottomNav, SettingsMenu) ändert niemand — die funktionieren bereits.
Mock-Fallback: Kein Backend? Kein Problem. Jede Seite fällt auf statische Testdaten zurück (→ app/lib/mockHome.ts). Der localhost läuft immer — egal ob Supabase konfiguriert ist oder nicht.
02 · Dateistruktur

Wo liegt was?

Next.js nutzt File-Based Routing: jede Datei namens page.tsx in einem Ordner wird automatisch eine URL. Kein manuelles Router-Setup nötig.

File-Based Routing

Ordnerstruktur = URL-Struktur. app/habits/page.tsx → localhost/habits. Keine Router-Konfiguration nötig.

Benennungskonvention

page.tsx = eine Route
layout.tsx = Shell um mehrere Routen
GROSSBUCHSTABEN.tsx = Komponente (kein eigener URL)
route.ts = API-Endpoint

@modal/(.)create ist eine sogenannte "Intercepting Route" — die Habits-Page bleibt sichtbar während das Formular-Sheet darüber liegt. Mehr dazu in Abschnitt 08.
03 · TypeScript-Konzepte

Was ist anders als HTML?

TypeScript ist JavaScript mit Typen. Wenn du HTML und eine andere Sprache kennst, brauchst du nur 4 neue Konzepte.

1

interface / type — Der Datenvertrag

Aus app/lib/types.ts

Neu für HTML-Coder

Ein interface beschreibt die Form eines Objekts. Wie ein Formular-Template: es legt fest, welche Felder existieren müssen und welchen Typ sie haben.

TypeScript zeigt einen Fehler, wenn ein Objekt das Interface nicht erfüllt — bevor der Code läuft. Das verhindert Tippfehler und falsche Daten.

Analogie: Ein Formular-Vordruck. Wer ihn ausfüllt, muss alle Pflichtfelder angeben — und in der richtigen Art (Text, Zahl, etc.) 
// app/lib/types.ts

// Erlaubte Kategorien — nur diese 4 Strings
export type HabitCategory =
  'sport' | 'health' |
  'mental' | 'personal';

  habitid: string;
  title: string;
  category: HabitCategory; // nur die 4!

  doneToday: boolean;

2

useState — Die lebendige Variable

React's reaktiver Zustand

Wichtigstes Konzept 
// Normale JS-Variable: UI updatet sich NICHT
let habits = [];
habits = fetchedHabits; // ← Seite bleibt leer

// useState: bei Änderung rendert React neu
const [habits, setHabits] =
  useState<HomeHabit[]>([]);

setHabits(fetchedHabits); // ← UI updatet sofort

// Boolean-State: Sheet auf/zu
const [showCreate, setShowCreate] =
  useState(false);

// Loading-State: Spinner vs. Inhalt
const [loading, setLoading] =
  useState(true);

setValue() → React merkt die Änderung → Komponente rendert mit neuem Wert

3

Komponenten + Props — Wiederverwendbare Blöcke

HTML-Include, aber mit Logik und Parametern

Eine Komponente ist eine Funktion, die HTML zurückgibt. Props sind ihre Parameter — wie beim Funktionsaufruf, nur für UI-Blöcke.

BottomNav ist ein Beispiel: einmal geschrieben, in allen 4 Seiten eingebunden. Ändert sich die Nav, ändert sich alles auf einmal.

// app/components/home/HomeHeader.tsx (exakt)
function getGreeting(date: Date): string {
  const h = date.getHours();
  if (h < 5)  return 'Good night';
  if (h < 12) return 'Good morning';
  if (h < 17) return 'Good afternoon';
  if (h < 21) return 'Good evening';
  return 'Good night';
}

function formatDate(date: Date): string {
  return date.toLocaleDateString('en-US', {
    weekday: 'long', month: 'long', day: 'numeric'
  });
}

export function HomeHeader() {
  const now = new Date();
  return (
    <div className="flex items-center justify-between">
      <div>
        <h1>{getGreeting(now)}</h1>
        <p>{formatDate(now)}</p>
      </div>
      <SettingsMenu />
    </div>
  );
}

05 · Seitenaufbau

app/page.tsx — Die Home-Page seziert

Die Haupt-Page ist rein ein Kompositions-Layer: Sie lädt Daten und gibt sie an spezialisierte Komponenten weiter. Kein direkt geschriebenes HTML außer dem Container.

app/page.tsx
'use client'; // ← sagt Next.js: JavaScript im Browser aktiv (kein Server-only)

import { useEffect, useState } from 'react';
import { HomeHeader }     from './components/home/HomeHeader';
import { TodayHabitList } from './components/home/TodayHabitList';
import { BottomNav }      from './components/BottomNav';
import { HabitForm }      from './habits/create/HabitForm';
import { MOCK_HABITS, MOCK_DEFAULT_STREAK } from './lib/mockHome';

export default function Home() {
  // ── State: was diese Seite wissen muss ─────────────────────────────────
  const [habits, setHabits]         = useState<HomeHabit[]>([]);
  const [loading, setLoading]       = useState(true);
  const [showCreate, setShowCreate] = useState(false); // Sheet auf/zu

  // ── Daten laden (einmalig beim ersten Render) ──────────────────────────
  useEffect(() => {
    const fetchHabits = async () => {
      try {
        const res = await fetch('/api/habits');
        if (!res.ok) throw new Error('Failed to fetch habits');
        const rows = (await res.json()) as HabitApiRow[];
        const mapped = rows.map((row) => ({
          habitid: row.habitid, title: row.title,
          category: row.category,
          streakDays: MOCK_DEFAULT_STREAK, doneToday: false,
        }));
        setHabits(mapped.length > 0 ? mapped : MOCK_HABITS);
      } catch {
        setHabits(MOCK_HABITS); // kein Backend → Mock
      } finally {
        setLoading(false);
      }
    };
    fetchHabits();
  }, []);

  return (
    <div className="flex min-h-full flex-col">
      <main className="mx-auto max-w-md px-4 pt-4">

        <HomeHeader />                              // Greeting + Datum + Settings
        <TodayStatsRow  />                              // 3 leere Placeholder-Boxen
        <MomentumCard   />                              // leere Placeholder-Box
        <TodayHabitList habits={habits} onToggle={toggleHabit} />

        <button onClick={() => setShowCreate(true)}>+ New Habit</button>

      </main>

      /* Bottom Sheet (liegt über der ganzen Seite wenn open=true) */
      {showCreate && (
        <div className="fixed inset-0 z-50">
          <div onClick={() => setShowCreate(false)} /> // Backdrop tap → close
          <HabitForm onClose={() => setShowCreate(false)} />
        </div>
      )}

      <BottomNav />
    </div>
  );
}

07 · Navigation & Bottom Sheet

Das Formular-Sheet über der Habits-Page

Wenn der User auf "+ New" tippt, soll die Habits-Page sichtbar bleiben während das Formular hochkommt. Das löst Next.js mit "Intercepting Routes".

Wie funktioniert das technisch?

Next.js "Intercepting Routes" fangen die URL /habits/create ab und rendern stattdessen den Sheet — während die Habits-Page als Hintergrund montiert bleibt.

app/habits/
├── layout.tsx          ← beide Slots: {children} {modal}
├── page.tsx            ← bleibt sichtbar (= {children})
└── @modal/
    ├── default.tsx     ← rendert null wenn kein Sheet
    └── (.)create/
        └── page.tsx   ← das Sheet (= {modal})
Home-Page nutzt denselben Sheet-Effekt, aber mit lokalem useState(false) statt Routing — da sie kein Layout mit Parallel Routes hat.
// FEATURE ENTRY POINT app/habits/@modal/(.)create/page.tsx — hier lebt die Sheet-Logik für den Habits-Tab. Das Formular selbst ist in HabitForm.tsx ausgelagert und wird von beiden Stellen (Home + Habits) geteilt.
08 · Feature Entry Points

Wo du dein Feature einbaust

Überall im Code wo ein echtes Feature noch fehlt steht ein Kommentar. Der Kommentar sagt was gebraucht wird, welche API-Endpoint vorgesehen ist und was der Placeholder macht.

Muster: So sieht ein Entry Point aus

// FEATURE ENTRY POINT: hier klickt der User → POST /api/check-ins
// Payload: { habitId: string, date: string, done: boolean }
// Momentan: nur lokaler State (doneToday flip) — kein Server-Call.
const toggleHabit = (habitid: string) => {
  setHabits((prev) =>
    prev.map((h) =>
      h.habitid === habitid
        ? { ...h, doneToday: !h.doneToday }
        : h
    )
  );
};

11 · Code Walkthrough I

BottomNav.tsx — Zeile für Zeile

Diese Datei ist perfekt zum Lernen: sie ist kurz, überschaubar und zeigt 4 der wichtigsten Konzepte auf einmal. Lies den Code von oben nach unten wie eine Geschichte.

'use client';
Pflicht für Interaktivität

Diese erste Zeile sagt Next.js: "Diese Datei läuft im Browser" — nicht nur auf dem Server. Ohne sie kein JavaScript, kein Click-Handler, kein useState. Jede Datei die useState, usePathname oder Event-Handler benutzt braucht das.

import Link from 'next/link';
import { usePathname } from 'next/navigation';
Imports = Werkzeuge holen

Link ist wie ein <a href> — aber schlauer: er lädt nur was sich ändert, nicht die ganze Seite neu.

usePathname() ist ein sogenannter Hook (Funktion von React/Next.js) der die aktuelle URL zurückgibt. Damit weiß die Nav welcher Tab gerade aktiv ist.

type Tab = {
  href: string;
  label: string;
  icon: React.ReactNode;
};

const TABS: Tab[] = [
  {
    href: '/',
    label: 'Home',
    icon: <svg ...>...</svg>,
  },
  { href: '/habits', label: 'Habits', icon: ... },
  { href: '/stats',  label: 'Stats',  icon: ... },
  { href: '/pet',    label: 'Pet',    icon: ... },
];
Daten getrennt von Darstellung

type Tab definiert wie ein Tab-Objekt aussehen muss: eine URL (href), ein Label-Text und ein Icon.

TABS ist ein Array (Liste) von 4 solchen Objekten — eines pro Tab. Großbuchstaben = konstant, ändert sich nie.

Der Trick: statt 4× denselben Button-Code zu schreiben, iteriert die Komponente über diese Liste. Neuen Tab hinzufügen = nur hier ein Objekt einfügen.

export function BottomNav() {
  const pathname = usePathname();
  // pathname = "/habits" wenn man auf
  // der Habits-Seite ist, "/" auf Home
export = von außen nutzbar

export function BottomNav() — diese Funktion gibt HTML zurück und ist damit eine React-Komponente.

export macht sie importierbar: import { BottomNav } from './BottomNav'.

usePathname() liest die URL live aus dem Browser — wenn der User navigiert, weiß die NavBar sofort welche Route aktiv ist, ohne dass die Seite neu lädt.

{TABS.map((tab) => {

  // "/habits" auch "/habits/create" etc.

.map() = für jeden Eintrag

TABS.map((tab) => ...) iteriert über alle 4 Tabs und gibt für jeden ein <Link>-Element zurück. Stell dir vor, map() sagt: "Für jeden Tab in der Liste, mach das hier draus."

Active-Check: Home (/) muss exakt matchen — sonst wäre /habits auch Home. Alle anderen nutzen startsWith, damit auch Unterseiten wie /habits/create den Habits-Tab aktiv zeigen.

Teal vs. grau: Das Ternär active ? 'teal' : 'grau' — wie ein Kurzform-If: wenn aktiv → teal-Farbe, sonst grau.

<Link key={tab.href} ...>
key — Pflicht in Listen

Wenn React eine Liste rendert, braucht jedes Element ein eindeutiges key-Attribut. Damit weiß React welches Element welches ist, wenn sich die Liste ändert. Ohne key: Warnung in der Konsole und mögliche Bugs beim Updaten. Als Key nimmt man immer was eindeutiges — hier die URL.

prev ist der aktuelle Wert von categories — React gibt ihn automatisch an die Setter-Funktion.

prev.includes(cat) — prüft ob die Kategorie schon drin ist.

prev.filter(c => c !== cat) — gibt ein neues Array ohne diesen Eintrag zurück. filter behält nur Elemente bei denen die Bedingung true ist.

[...prev, cat] — der Spread-Operator ... kopiert alle alten Einträge und fügt den neuen am Ende an. Arrays nie direkt mutieren — immer ein neues erstellen.

Warum nicht push()? React erkennt nur dann eine Änderung wenn ein neues Array-Objekt entsteht. push() mutiert das bestehende → React sieht keine Änderung → UI updatet nicht.

③ Submit: Validierung → API → Schließen

// app/habits/create/HabitForm.tsx (exakt)
const handleSubmit = async (e: React.FormEvent) => {
  e.preventDefault(); // ← verhindert Standard-Browser-Submit (würde Seite neu laden)

  // ── 1. Validierung — Kein API-Call wenn Daten fehlen ──────────────────────
  if (!title.trim() || categories.length === 0) {
    setModal({
      title: 'Missing info',
      message: 'Enter a habit name and pick at least one category.',
    });
    return; // ← früh raus, nichts weiter passiert
  }
  if (!Object.values(frequenz).some(Boolean)) {
    setModal({
      title: 'Missing info',
      message: 'Select at least one day.',
    });
    return;
  }

  // ── 2. Ladestate an ────────────────────────────────────────────────────────
  setLoading(true); // → Button zeigt "Adding…", ist disabled

  try {
    // ── 3. API-Call ──────────────────────────────────────────────────────────
    const res = await fetch('/api/habits', {
      method: 'POST',
      headers: { 'Content-Type': 'application/json' },
      // FEATURE ENTRY POINT: auch color, icon, alle categories senden
      body: JSON.stringify({ title, category: categories[0], frequenz }),
    });
    if (!res.ok) throw new Error('Failed to create habit');

    // ── 4. Erfolg: Server-Daten refreshen + Sheet schließen ──────────────────
    router.refresh(); // ← sagt Next.js: Server Components neu rendern
    onClose();        // ← kommt als Prop von der Parent-Komponente

  } catch (err) {
    // ── 5. Fehlerfall ────────────────────────────────────────────────────────
    setModal({
      title: 'Error',
      message: err instanceof Error ? err.message : 'Unknown error',
    });
  } finally {
    // ── 6. Immer: Ladestate aus ──────────────────────────────────────────────
    setLoading(false);
  }
};
try / catch / finally — wie ein Sicherheitsnetz:
try = versuch das. catch = wenn's schiefgeht, mach das. finally = mach das immer, egal was passiert (perfekt für Ladestate aus).
await = warte auf das Ergebnis bevor du weitermachst. Ohne await würde der Code weiterlaufen bevor die API geantwortet hat — der Response wäre dann noch nicht da.

{condition && <JSX/>} — der && Operator in JSX: wenn die linke Seite true ist, wird die rechte Seite gerendert. Wenn false — gar nichts.

condition ? 'A' : 'B' — Ternär-Operator: wenn condition true → zeige A, sonst B. Kein if-Block nötig direkt im JSX.

Fazit: In React gibt es kein separates Template-System. Alles — Schleifen, Bedingungen, Daten — passiert direkt in den {} im JSX mit normalem JavaScript.
